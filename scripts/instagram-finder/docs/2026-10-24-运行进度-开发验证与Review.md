# 运行进度：开发验证与Review

## 实施与范围

新增progress.mjs（111行）实现最新小快照和对现有CLI子进程的观察。正式batch首个合法save后启动，runtime动作/上下文、session普通节奏及显式等待更新内存标量；父CLI每15秒读取progress.json输出一行进度。没有新增浏览器请求、新进程、后台守护或自动重试；没有在每次heartbeat复制/序列化完整作者表。

执行/等待期间AI持续保留执行会话并30～60秒主动更新的操作约定已写入README及启动交接。项目代码不能强制控制Codex客户端图标，本轮没有修改客户端。状态文件是最近观察，异常退出以父进程事件为准，不能将残留running快照当活跃证明。

## 性能实测

证据：runs/2026-10-24-ins-progress-validation/performance-results.json、leak-stress-results.json、demo-output-final.jsonl。

使用Node真实父子进程和文件IO、默认15秒周期、1000条既有作者（每条附约1KB Bio），执行31秒长等待。排除浏览器、网站及原有采集器的资源开销；CPU为CPU时间/墙钟时间，按单核100%计算，非系统总体占用。

| 指标 | 结果 |
|---|---|
| worker CPU时间/平均占用 | 36.338ms / 31.005s，约0.117%单核 |
| 父观察器CPU时间/平均占用 | 28.051ms / 31.061s，约0.090%单核 |
| 两者合计平均CPU | 约0.208%单核 |
| worker状态写入 | 4次，共1615字节（同一小文件原子替换） |
| worker GC后heap净增 | 25816字节 |
| 1000次启停 | 结束后无新增Timeout、无后续写入；heap净增67584字节 |
| 独立5000次进度/观察器启停 | 每1000次GC后净增10208、63456、142736、177848、169568字节；末轮回落，每轮残余Timeout均0，监听器均已移除 |
| 异常退出 | child exit2，立即明确输出interrupted及workerState=unknown，未伪报成功 |

结论：在本次单用户、1000作者样本下，新增进度机制CPU及IO消耗低；未发现定时器/监听器泄漏或终态后持续写入。短时压力测试不能证明任意长运行绝无泄漏，也不代表浏览器、第三方页面或原有采集逻辑整体资源占用。
