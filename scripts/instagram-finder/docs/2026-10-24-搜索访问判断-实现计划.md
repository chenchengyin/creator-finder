# 搜索访问判断 Implementation Plan

> **For agentic workers:** 使用 superpowers:executing-plans 在当前对话逐任务执行。

**Goal:** 搜索访问错误可归属、可解释，正常搜索真正进入目标结果。
**Architecture:** 新增搜索专用响应分析器；搜索pager负责原生事件与页面状态；runtime保存证据；batch保存暂停信息。
**Tech Stack:** Node.js ESM / node:test / Ego Lite，无新依赖。
**Spec:** 2026-10-24-搜索访问判断-设计.md

## Global Constraints

原空间；不拼接搜索导航URL、不重放请求、不自动重试；保留已核验作者、旧断点schema和其他平台规则。

## Review Focus

1. 旧请求晚到及未知操作归属（SEARCH-001）。
2. 登录和限流文字同现时优先级（SEARCH-002）。
3. data与errors并存但必要字段缺失（SEARCH-003）。
4. 存储失败被吞或敏感字段泄漏（SEARCH-004）。
5. 账号建议被误当最终结果、恢复丢页（SEARCH-005/006）。

## Task 1：分类与证据

流程：原生请求/响应→关联→提取允许字段→分类→采纳/告警/暂停。
伪代码：analyzeSearchResponse(context)返回evidence、page或error；非目标失败仅告警，显式会话验证停止。
注意：未知不等于可忽略；无有效结果时仍暂停。

## Task 2：入口及持久化

流程：首页→官网搜索控件→Enter→实际结果链接/结果状态→关联原生页→断点。
伪代码：runtime注入onEvidence；batch catch保存accessIssue与待消费页；成功恢复清除旧暂停原因。
注意：证据先持久化再采纳；保存失败停止；不主动恢复历史空间或批次。
