# 前N位强制主页核验需求Review

方式：Brainstorming bounded只读需求Review。范围为同目录设计、测试用例、实现计划，以及既有config/workflow/profile/browser行为和当前运行停止状态。输出为明确缺口、修正及验收覆盖；不修改生产代码，不把需求Review称为代码Review。

## 已明确的业务选择

用户确认N=10，随后明确选择“否，搜索仍翻到底，前10位强制查主页，其余沿用原筛选规则”。本次不把N当搜索停止上限、不只处理10人、不改变硬性邮箱/地区/均播条件。站外邮箱抓取不在本次范围，现有22位任务仍停止待人工核验。

## 发现并补齐的流程缺口

| 缺口 | 影响 | 收敛与验证 |
|---|---|---|
| 全局queue顺序不能代表当前词排名 | 可能查错前10人 | 按当前词原响应首次作者顺序独立持久化，顺序-ORDER-001/002 |
| 只改配置N不会绕过profile早退 | 前10仍会因signature无邮箱被跳过 | 预筛加明确强制上下文，主页-PROFILE-001/002 |
| 旧processedKeywords可能已包含该词 | 旧预筛排除被误作主页完成 | 本批基本主页/挂链完成标记优先，缓存-CACHE-001/002 |
| 同一人多视频或跨词重复 | 人数/动作重复，或补足10个新作者改变范围 | 按稳定ID去重，跨词复用本批结果，各词前N独立归属 |
| 外链缺失与空值混淆 | 搜索没给字段就误判无链 | 主页状态present/none/unknown，保留字段/DOM来源；外链-LINK-001至003 |
| 有外链容易被误算邮箱达标 | 放宽用户未授权的邮箱来源 | URL仅记录，不访问站外；邮箱-EMAIL-003 |
| 失败时替补第11人 | 隐藏前10中的未完成检查 | 保存原前10断点，访问失败按旧规则暂停/记缺口，不凑人数 |
| 批次重启或窗口变化 | 重复/漏查或旧统计冒充当前均播 | 冻结参数、本批归属与窗口校验，断点-RESUME与缓存-CACHE用例 |
| 前10与整批目标停止冲突 | 虚报全部完成 | 原显式目标停止优先保留部分状态，如实记录，断点-RESUME-002 |
