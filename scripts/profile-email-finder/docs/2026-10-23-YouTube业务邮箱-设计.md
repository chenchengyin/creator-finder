# YouTube业务邮箱集成 · 设计

集成来源：用户指定对话 01a163ea-9352-7d82-a398-d9a17c788eb0 的已验证可见页面流程，未复制其历史邮箱作为实测结果。

流程：频道简介“更多” → 原生“查看电子邮件地址” → 观察普通 reCAPTCHA 勾选框 → 勾选一次 → 等待 aria-checked=true → 原生“提交” → 等待 About 内可见 mailto。

新增 youtube-email.mjs 负责状态判断、稳定点击和阶段检查点。browser.mjs 接入该流程；finder.mjs 将 profile_contact_email 作为主页明确联系邮箱来源；integration.mjs 返回 sourceType=profile_contact。保持与 bio、linked_site 的区别，邮箱字符串仍由共用解析器处理。

点击先完成全局访问间隔，再检查页面状态及验证状态，滚动到控件、等待两个动画帧、检查实际命中后点击。session.mjs 为鼠标点击记录原有共享节奏和日志。

实测发现 YouTube 自定义元素的 hidden 属性可返回 Symbol(Yf)，不能用 truthy 判断隐藏。统一改为 hidden===true 或实际 hidden 属性，并保留计算样式和尺寸检查。原生验证 iframe 异步加载时也等待实际就绪后再推进。

原生联系信息表格有邮箱提示但控件未加载时，最多等待6秒；仍未识别则保存暂停。作者自由简介提到 email address 不会因此暂停，也不会阻断正常站外挖掘。只接受可见原生 About 邮箱作为原生流程成功条件。

勾选最多一次，提交最多两次，每次都需要验证通过；图片挑战、验证未完成、401/403、429、登录墙、控制异常保存暂停。不得解题或绕过验证。借用页面的调用方掌握生命周期，实测成功保存证据后才 finish；中途失败不结束空间。
